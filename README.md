# OpenCode 换肤助手（Windows）

给 Windows 版 OpenCode 桌面端换背景图和配色的小工具：选一张本地图片，自动取色、调节遮罩与模糊，
先在模拟预览里看清效果，再决定要不要写进应用；随时可以恢复。

**它是非官方的第三方本地定制工具**，与 OpenCode 官方无关。

> **第一次用？直接跳到 [新手一步一步](#新手一步一步照着做就行)，别看别的。**

---

## 它做什么 / 不做什么

| 做 | 不做 |
|---|---|
| 从本地图片提取代表色，生成一套语义配色 | 不联网、不上传图片、不采集任何数据 |
| 调节背景遮罩、面板不透明度、模糊、明暗、主色 | 不修改可执行文件、不改安全开关、不强制结束进程 |
| 写入应用归档内的 3 个条目（见下） | 不碰终端配色、不碰代码语法高亮 |
| 应用前自动备份，支持恢复原版 / 上一主题 | 不提供「破解」「去限制」之类能力 |

## 支持范围

| 项 | 值 |
|---|---|
| 系统 | Windows 10/11 x64 |
| 目标 | OpenCode 桌面版，`@opencode-ai/desktop`，用户级安装 |
| **已验证版本** | **1.18.29**（其余版本一律标记为 `unknown`，只能预览，不能应用） |
| 安装位置 | 只扫明确登记的位置（`%LOCALAPPDATA%\Programs\@opencode-aidesktop` 与卸载登记表登记的路径），不做全盘搜索 |

版本不在白名单时，界面会显示 `unknown` 并给出原因——这是刻意的：没验证过的版本不允许写入。

## 新手：一步一步照着做就行

### 开始前：只做一件事

**把 OpenCode 完全退出。**

不是关掉窗口就算——看屏幕右下角的托盘区（时间旁边，可能要点那个小箭头展开），
还有没有 OpenCode 的图标。**有就右键它 → 退出。**

它在运行的时候，工具不会写入，只会提示你「目标应用正在运行」。这是保护，不是故障。

其余什么都不用准备。

### 第 1 步：选一张图

打开换肤助手 → 点左边的 **「选择图片」** → 挑一张图。

支持 PNG / JPEG（.jpg/.jpeg/.jfif/.jpe）/ WebP，最大 20 MB。也可以直接把图片**拖**到那个虚线框里。
扩展名只用于筛选，格式按文件内容识别：如果后缀和实际内容不一致，界面会如实说明。

选完等一两秒，中间会自动出现预览。

> 想先随便试试？找一张风景照或壁纸就行，不喜欢随时能改回来。
> 原图只是被读取，不会被移动、修改、上传。

### 第 2 步：把滑条调到「字看得清」

左边有三个滑条、一个下拉框。不知道怎么调，就照下面来：

| 项目 | 一句话解释 | 字看不清时 |
|---|---|---|
| **背景遮罩** | 在图片上盖一层底色。盖得越多，图越淡、字越清楚 | **往右拉** |
| **面板不透明度** | 侧栏、聊天框这些面板有多实。越实字越清楚 | **往右拉** |
| **背景模糊** | 把背景图糊化，糊一点更有质感 | 随意，不影响清晰度 |
| **明暗模式** | 浅色 / 深色 / 跟随图片 | 亮的图选浅色，暗的图选深色 |

右边「可读性检查」会实时告诉你每一行字够不够清楚，达标的打勾、不达标的标红。

**只要有一行不达标，「应用到 OpenCode」这个按钮就是灰的，点不动。**
这不是坏了，是它不让你去做一份看不清的皮肤。想点得动，就把「背景遮罩」往右拉。

### 第 3 步：应用

点 **「应用到 OpenCode」**。

会弹出一个确认框，里面写着：装在哪、什么版本、会改哪几个文件、备份放哪、要占多大空间。

**看一眼「安装位置」是不是你平时用的那个 OpenCode**，确认没错 → 点 **「确认应用」** → 等进度条走完。

> 点「确认应用」之前，什么都没有被改动。点取消就当没发生过。

### 第 4 步：重启 OpenCode，看效果

**这一步最容易忘：不重启看不到效果。**

关掉换肤助手，重新打开 OpenCode，背景图和配色就生效了。

### 不满意？改回来

重新打开换肤助手，右边「恢复」区有两个按钮：

- **「上一主题」** —— 回到上一次应用之前的样子。想换张图反复试就用它来回倒。
- **「原版」** —— 回到你第一次用本工具之前的出厂样子。

点完同样要 **重启 OpenCode**。

### 出问题了？看窗口最底下那一行

工具底部有一条状态栏，出错会变红，写清三件事：

**出了什么错 → 该怎么办 → 你的安装有没有被动过**

照着做就行。最常见的两个：

| 底部提示 | 怎么办 |
|---|---|
| 目标应用正在运行 | 把 OpenCode 完全退出（**包括右下角托盘图标**）再来 |
| 正文对比度 X 未达到 4.5 | 把「背景遮罩」往右拉 |

其他报错见下面「常见报错」一整节。

## 完整操作说明（想要细节看这里）

1. **选图**：点「选择图片」，或把 PNG / JPEG / WebP 拖进左侧虚线框（≤ 20 MiB，不支持 SVG）。
   JPEG 的标准别名 .jfif / .jpe 与 .jpg / .jpeg 同等对待；扩展名只做筛选，真实格式由内容判定。
   原图只读，不会被移动或修改。
2. **看预览**：中间是模拟预览，覆盖长文本、代码、链接、输入框、弹出菜单、按钮四态、错误提示、diff。
   预览下方那行小字请当真：**「模拟预览，真实效果取决于已验证版本」**。
3. **调节**：拖动遮罩 / 面板不透明度 / 模糊，切换明暗或指定主色。右侧「可读性检查」会按
   **图片 → 遮罩 → 面板三层合成后的实际底色**逐条给出对比度；有未达标项时，「应用」按钮会被禁用。
4. **应用**：点「应用到 OpenCode」→ 先做环境预检（应用是否在运行、目录是否可写、磁盘是否够）→
   弹出确认框（安装位置、版本、将要改的 3 个条目、备份位置、所需空间、非官方风险）→ 确认后才写入。
   写入前会备份，写入后会用 hash 复核；失败了会明确告诉你**安装有没有被改**。
5. **恢复**：右侧「恢复」区分两个入口 ——
   **上一主题**（回到应用前那版）与**原版**（回到本工具首次接管时的状态）。
   若首次接管时该安装已经被改过，原版不可确认，「恢复原版」会被禁用并说明原因。

> 应用完成后需要**重启 OpenCode** 才能看到效果。

## 恢复语义（重要）

- **原版**：本工具第一次接管该安装时的归档快照。只有确认它没被改过（`pristine`）才允许恢复。
- **上一主题**：上一次成功应用前的快照，只保留最近 3 份。
- 恢复本身也是一次**新的前向操作**，会先备份当前状态再写回，不会改写历史记录。
- 恢复前会检查目标版本是否变化：应用升级后旧备份不再适用，工具会拒绝恢复并提示重新应用。

## 非官方修改的风险

- 这是改写应用归档的第三方定制，**不是官方功能**。
- OpenCode 更新、修复安装或重装后，定制会失效，需要重新应用。
- 卸载前请先「恢复原版」，避免留下被改过的文件。
- 备份默认放在 `%LOCALAPPDATA%\OpenCodeThemeSwitcher\instances\<实例>\backups\`，
  每份约 150 MB 级；清理这个目录等于删掉恢复能力。

## 常见报错

| 提示 | 含义 | 怎么办 |
|---|---|---|
| 目标应用正在运行 | 检测到 OpenCode 进程 | 保存任务后完全退出 OpenCode 再试；工具不会强制结束进程 |
| 无法确认目标应用是否已退出 | 进程查询失败，不能当成「没运行」 | 手动确认任务栏与托盘没有 OpenCode 后重试 |
| 磁盘空间不足 | 需要约「归档 ×3 + 64 MB」 | 清理磁盘；空间不足时不会开始写入 |
| 没有写入权限 | 目标目录不可写 | 改用用户级安装，或以有写权限的账户运行 |
| 目标在准备之后发生了变化 | 准备到应用之间归档被改动（可能已自动更新） | 重新准备并再次应用 |
| 正文对比度 X 未达到 4.5 | 参数下文字读不清 | 调高遮罩或面板不透明度 |
| 无法确认为原版，恢复原版已禁用 | 首次接管时该安装已被改过 | 只能用「上一主题」；要出厂状态请重新安装 OpenCode |
| 主题已写入，但操作记录写入失败 | 写入成功但记账失败 | 不要手动替换文件，用「恢复」入口或重新应用补齐记录 |

## 已知限制

- **真机视觉走查未完成**：功能闭环已在「真实 Electron 主进程 + 真实窗口 + 合成安装」上验证
  （`npm run test:e2e:electron` 35 项、`npm run test:e2e` 8 项），
  但 OpenCode 真实安装上的画面观感仍需人工逐项确认（详见 `docs/acceptance.md` 第 5.3、6.3 节）。
- **没有「恢复原版」入口，除非登记出厂指纹**：原版必须由证据证明，不能靠「没看到本工具的标记」
  推断（详见 `docs/original-evidence.md`）。没有证据时可用的是「恢复到首次接管时」。
- 已验证版本只有 1.18.29；其他版本只能预览。token 映射取自该版本的官方 CSS，
  应用升级后需要重新核对（见 `docs/discovery.md`）。
- 来源不明的第三方主题层会**直接拒绝**应用（`THEME_CONFLICT`），工具不自动覆盖。
- 备份是整档复制（150 MB 级），不是增量；保留最近 3 份。
- 便携包未签名；未做代码签名，不要对外声称已签名。`release2/` 是旧构建，
  本轮改动后需要重新打包。
- 图片只支持 PNG / JPEG（.jpg/.jpeg/.jfif/.jpe）/ WebP，≤ 20 MiB，不支持 SVG。
  GIF / AVIF / TIFF / BMP / HEIC 尚未开放（GIF、AVIF、TIFF 的解码器本机可用，属于第二批；
  见 `handoff/format-review-2026-09-12/NEXT_EXECUTION_PLAN.md`）。
- 背景条目在归档里固定叫 `oc-theme-background.jpg`，非 JPEG 内容也会落在这个名字下
  （当前按原图字节写入，未做规范化；统一编码与改名属于第二批 T4/T6）。
- 终端（.xterm）与 `--syntax-*` / `--markdown-*` 语法色不在覆盖范围内（有意为之）。

## 开发命令

```bash
npm install
npm run dev            # 起 Vite（界面热更新）
npm run typecheck      # tsc --noEmit
npm run lint           # eslint
npm run test:unit      # 单元
npm run test:integration   # 集成（合成安装 + 故障注入 + 真实 Electron 主进程）
npm run test:e2e       # 真实窗口闭环（Playwright + Electron）
npm run test:e2e:electron   # 主进程闭环（不建窗口，无显示会话也能跑）
npm run verify         # 类型 + lint + 单测 + 集成 + 构建 + E2E
npm run build          # 构建主进程与界面到 out/
npm run audit          # 交付前自检：路径/凭证/产物/许可/IPC
npm run dist           # 便携包（dir 目标，见下方镜像说明）
npm start              # 用已构建的 out/ 启动（开发用）
```

`npm run dist` 需要下载 Electron 发行包与 electron-builder 二进制，直连 GitHub 可能超时，可用镜像：

```bash
ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/ \
ELECTRON_BUILDER_BINARIES_MIRROR=https://npmmirror.com/mirrors/electron-builder-binaries/ \
npx electron-builder --win --dir
```
