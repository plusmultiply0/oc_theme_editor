# OpenCode 换肤助手（Windows）

给 Windows 版 OpenCode 桌面端换背景图和配色的小工具：选一张本地图片，自动取色、调节遮罩与模糊，
先在模拟预览里看清效果，再决定要不要写进应用；随时可以恢复。

**它是非官方的第三方本地定制工具**，与 OpenCode 官方无关。

> **第一次用？直接跳到 [新手一步一步](#新手一步一步照着做就行)，别看别的。**

---

## 它做什么 / 不做什么

| 做 | 不做 |
|---|---|
| 从本地图片提取代表色，生成一套语义配色 | 不联网、不上传图片、不采集任何数据 |
| 调节背景遮罩、面板不透明度、模糊、明暗、主色 | 不修改可执行文件、不改安全开关、不强制结束进程 |
| 写入应用归档内的 3 个条目（见下） | 不碰终端配色、不碰代码语法高亮 |
| 应用前自动备份，支持恢复上一主题 / 首次接管快照（原版需出厂指纹证据） | 不提供「破解」「去限制」之类能力 |

## 支持范围

| 项 | 值 |
|---|---|
| 系统 | Windows 10/11 x64 |
| 目标 | OpenCode 桌面版，`@opencode-ai/desktop`，用户级安装 |
| **已验证版本** | **1.18.29**（白名单，完整真机验证）；其余版本若通过代码结构验证会显示「结构验证通过」，可确认后应用；两者都不满足则只能预览、不能应用 |
| 安装位置 | 只扫明确登记的位置（`%LOCALAPPDATA%\Programs\@opencode-aidesktop` 与卸载登记表登记的路径），不做全盘搜索 |

版本不在白名单时不再一票否决：工具会做只读的**代码结构验证**（注入锚点唯一、待写条目归属干净），
通过则标记 `结构验证通过`（提示蓝徽章，区别于白名单绿），应用前会再弹一次逐项确认框。
注意边界：结构验证 ≠ 完整真机验证，界面细节仍可能有未预期的样式偏差；不通过则只允许预览、不允许写入。

## 新手：一步一步照着做就行

### 开始前：只做一件事

**把 OpenCode 完全退出。**

不是关掉窗口就算——看屏幕右下角的托盘区（时间旁边，可能要点那个小箭头展开），
还有没有 OpenCode 的图标。**有就右键它 → 退出。**

它在运行的时候，工具不会写入，只会提示你「目标应用正在运行」。这是保护，不是故障。

可以先确认三件事：安装路径认得对、磁盘剩余空间够（预检会给出具体数字）、
以及你知道备份会落在哪里（见文末「非官方修改的风险」）。

### 第 1 步：选一张图

打开换肤助手 → 点左边的 **「选择图片」** → 挑一张图。

支持 PNG / JPEG（.jpg/.jpeg/.jfif/.jpe）/ WebP，最大 20 MiB。也可以直接把图片**拖**到那个虚线框里。
扩展名只用于筛选，格式按文件内容识别：如果后缀和实际内容不一致，界面会如实说明。

选完等一两秒，中间会自动出现预览。

> 想先随便试试？找一张风景照或壁纸就行，不喜欢随时能改回来。
> 原图只是被读取，不会被移动、修改、上传。

### 第 2 步：把滑条调到「字看得清」

左边有三个滑条、一个下拉框。不知道怎么调，就照下面来：

| 项目 | 一句话解释 | 字看不清时 |
|---|---|---|
| **背景遮罩** | 在图片上盖一层底色。盖得越多，图越淡、字越清楚 | **往右拉** |
| **面板不透明度** | 侧栏、聊天框这些面板有多实。越实字越清楚 | **往右拉** |
| **背景模糊** | 把背景图糊化，糊一点更有质感 | 随意，不影响清晰度 |
| **明暗模式** | 浅色 / 深色 / 跟随图片 | 亮的图选浅色，暗的图选深色 |

右栏「检查」选项卡会实时给出可读性结论：达标与否、代表性底色、余量最差的一项；
点开「明细与判定依据」可看逐条。

**只要有一项不达标，「应用到 OpenCode」按钮就是灰的。**
这不是坏了，是它不让你做一份看不清的皮肤；把「背景遮罩」往右拉即可解锁。

### 第 3 步：应用

点 **「应用到 OpenCode」**。

如果顶栏徽章是「结构验证通过」（非白名单版本经结构验证放行的通道），会先弹一个逐项确认框，
列出锚点/变更集合/unpacked 三项检查结论；核对无误点 **「我了解，继续」** 才进入下面的流程。

会弹出一个确认框，里面写着：装在哪、什么版本、会改哪几个文件、备份放哪、要占多大空间。

**看一眼「安装位置」是不是你平时用的那个 OpenCode**，确认没错 → 点 **「确认应用」** → 等进度条走完。

> 点「确认应用」之前，什么都没有被改动。点取消就当没发生过。

### 第 4 步：重启 OpenCode，看效果

**这一步最容易忘：不重启看不到效果。**

关掉换肤助手，重新打开 OpenCode，背景图和配色就生效了。

状态栏最左侧有 **「启动 OpenCode」** 按钮，应用完直接点它——走的是和你双击图标同一条
系统启动路径，对话照常加载；检测到 OpenCode 已在运行时变成 **「打开 OpenCode」**
（单实例应用，只会把已有窗口带到前台）。它只负责启动，不碰文件。

### 不满意？改回来

重新打开换肤助手，切到右栏「恢复」选项卡，最多有三个入口（按你机器上有没有对应快照出现）：

- **「恢复上一主题」** —— 回到上一次应用之前的样子。想换张图反复试就用它来回倒。
- **「恢复到首次接管时」** —— 回到本工具第一次接管这个安装时的状态。
  这是**最诚实的兜底入口**：它就是你机器当时的样子，不承诺是出厂界面。
- **「恢复原版」** —— **只有**在本工具登记过该版本的出厂指纹、并且备份与指纹吻合时才会出现。

三者的详解见下面「恢复语义」。点完同样要 **重启 OpenCode**。

### 出问题了？看窗口最底下那一行

工具底部有一条状态栏，出错会变红，写清三件事：

**出了什么错 → 该怎么办 → 你的安装有没有被动过**

照着做就行。最常见的两个：

| 底部提示 | 怎么办 |
|---|---|
| 目标应用正在运行 | 把 OpenCode 完全退出（**包括右下角托盘图标**）再来 |
| 正文对比度 X 未达到 4.5 | 把「背景遮罩」往右拉 |

其他报错见下面「常见报错」一整节。

## 完整操作说明（想要细节看这里）

1. **选图**：点「选择图片」，或把 PNG / JPEG / WebP 拖进左侧虚线框（≤ 20 MiB，不支持 SVG）。
   JPEG 的标准别名 .jfif / .jpe 与 .jpg / .jpeg 同等对待；扩展名只做筛选，真实格式由内容判定。
   原图只读，不会被移动或修改。
2. **看预览**：中间是模拟预览，覆盖长文本、代码、链接、输入框、弹出菜单、按钮四态、错误提示、diff。
   预览下方那行小字请当真：**「模拟预览，真实效果取决于已验证版本」**。
3. **调节**：拖动遮罩 / 面板不透明度 / 模糊，切换明暗或指定主色。右栏「检查」选项卡
   按**图片 → 遮罩 → 面板三层合成后的实际底色**给出结论与余量最差项，明细在
   「明细与判定依据」里展开看；有未达标项时「应用」仍可点击，但会先弹出确认框，
   需要你显式接受后果才会写入（放行与未达标清单会记入操作记录，随时可恢复）。
4. **应用**：点「应用到 OpenCode」→ 先做环境预检（应用是否在运行、目录是否可写、磁盘是否够）→
   弹出确认框（安装位置、版本、将要改的 3 个条目、备份位置、所需空间、非官方风险）→ 确认后才写入。
   写入前会备份，写入后会用 hash 复核；失败了会明确告诉你**安装有没有被改**。
5. **恢复**：右栏「恢复」选项卡最多三个入口 ——
   **恢复上一主题**（回到应用前那版）、**恢复到首次接管时**（回到本工具第一次接管时的状态，
   不承诺出厂界面）、以及**恢复原版**（仅当该版本登记过出厂指纹且与备份吻合时才出现）。
   没有出厂指纹证据时，「恢复原版」**不会出现**，面板会写明原因。

> 应用完成后需要**重启 OpenCode** 才能看到效果。

## 恢复语义（重要）

- **上一主题**：上一次成功应用前的快照，只保留最近 3 份。
- **首次接管快照**：本工具第一次接管该安装时的归档快照。它是「最接近你没动过时的状态」，
  但**不承诺等于出厂原版**——接管时安装可能已经被别的工具改过。
- **原版**：需要**证据**。只有当内置指纹表里登记了该版本、且备份哈希与指纹吻合时才叫原版；
  当前内置指纹表**为空**，所以默认不会出现「恢复原版」入口（补录方式见 `docs/original-evidence.md`）。
- 恢复本身也是一次**新的前向操作**，会先备份当前状态再写回，不会改写历史记录。
- 恢复前会检查目标版本是否变化：应用升级后旧备份不再适用，工具会拒绝恢复并提示重新应用。

## 非官方修改的风险

- 这是改写应用归档的第三方定制，**不是官方功能**。
- OpenCode 更新、修复安装或重装后，定制会失效，需要重新应用。
- 想撤销修改：先点「恢复上一主题」或「恢复到首次接管时」，按提示重启后确认；
  **没有可验证的出厂备份时不承诺回到出厂状态**，要彻底回出厂请重新安装 OpenCode。
- 直接删掉工具目录**不等于撤销主题**：归档里的定制还在。恢复能力也存在这个目录里，
  删掉就等于放弃恢复。
- 备份默认放在 `%LOCALAPPDATA%\OpenCodeThemeSwitcher\instances\<实例>\backups\`，
  每份约 150 MB 级；清理这个目录等于删掉恢复能力。

## 常见报错

| 提示 | 含义 | 怎么办 |
|---|---|---|
| 目标应用正在运行 | 检测到 OpenCode 进程 | 保存任务后完全退出 OpenCode 再试；工具不会强制结束进程 |
| 无法确认目标应用是否已退出 | 进程查询失败，不能当成「没运行」 | 手动确认任务栏与托盘没有 OpenCode 后重试 |
| 磁盘空间不足 | 需要约「归档 ×4 + 64 MiB」（备份 + 解包准备区 + 重打包产物 + 目标侧临时副本） | 清理磁盘；空间不足时不会开始写入 |
| 没有写入权限 | 目标目录不可写 | 改用用户级安装，或以有写权限的账户运行 |
| 目标在准备之后发生了变化 | 准备到应用之间归档被改动（可能已自动更新） | 工具会先对新归档重跑结构验证：通过则按新版本继续写入；不通过则拒绝，重新准备并再次应用 |
| 正文对比度 X 未达到 4.5 | 参数下文字读不清 | 调高遮罩或面板不透明度 |
| 没有可证明的原版 | 该版本未登记出厂指纹（当前指纹表为空） | 用「恢复上一主题」或「恢复到首次接管时」；要出厂状态请重新安装 OpenCode |
| 主题已写入，但操作记录写入失败 | 写入成功但记账失败 | 不要手动替换文件，用「恢复」入口或重新应用补齐记录 |

## 三种「看到效果」不是一回事

新手最容易混淆的地方，这里说清楚：

| 说法 | 含义 | 能证明什么 |
|---|---|---|
| **模拟预览** | 左侧那块仿界面，用同一套层级参数画出来的 | 只能说明配色与透明度大致合理，**不代表**真实窗口长这样 |
| **资源已写入** | 确认框走完、归档被替换、提交后用 hash 复核过 | 说明写进去了、内容对得上；**还没证明你看到的画面是对的** |
| **真实窗口验收通过** | 完全重启 OpenCode 后，人工逐项看过首页/会话/侧栏/输入/菜单/弹层 | 这才是「背景确实出来了」 |

工具会在写入后提示你「完全退出并重启 OpenCode 再确认」，就是让你走到第三步。
恢复操作也一样：恢复完要重启再看。

## 出问题了，怎么反馈

给这些信息就能定位（**不需要**发图片、聊天记录或完整用户目录）：

1. 工具版本（标题栏或候选包名）与候选包 SHA256（如果知道）；
2. 报错码与那行中文提示（状态栏那行原文照抄即可）；
3. 操作时间（精确到分钟）；
4. 目标 OpenCode 版本；
5. 如果界面有「待恢复」提示，把它显示的操作 ID 一并给出。

日志目录：`%LOCALAPPDATA%\OpenCodeThemeSwitcher\`（按实例子目录组织）。
发之前请自行确认里面没有你不想公开的内容——它记录的是路径与哈希，不含图片内容和你与 AI 的对话。

### 中文显示成乱码时

仓库里的源码、日志与工具输出统一是 **UTF-8**。如果你在 Windows PowerShell 5.1 里读到乱码，
问题通常在**读取端按 ANSI/GBK 解码**，而不是文件坏了：

- 读文件显式指定编码：`Get-Content <文件> -Encoding UTF8`（PowerShell 7、VS Code 默认就是 UTF-8）；
- 终端里直接跑 `npm run release:build` 等命令看到乱码时，先 `chcp 65001` 把控制台代码页切到 UTF-8；
- 工具侧已把 PowerShell 子进程的 stdout 钉成 UTF-8（`tools/ps-run.cjs`），并由
  `tests/unit/encoding.test.ts` 守住两条规则：项目文本必须是合法 UTF-8（无 BOM/无乱码残留）、
  不得绕过统一入口裸调 PowerShell。

## 开发命令

```bash
npm install
npm run dev            # 起 Vite（界面热更新）
npm run typecheck      # tsc --noEmit
npm run lint           # eslint
npm run test:unit      # 单元
npm run test:integration   # 集成（合成安装 + 故障注入 + 真实 Electron 主进程）
npm run test:e2e       # 真实窗口闭环（Playwright + Electron）
npm run test:e2e:electron   # 主进程闭环（不建窗口，无显示会话也能跑）
npm run verify         # 类型 + lint + 单测 + 集成 + 构建 + E2E
npm run build          # 构建主进程与界面到 out/
npm run audit          # 交付前自检：路径/凭证/产物/许可/IPC
npm run dist           # 仅开发自用：便携包落 release-dev/（见下方镜像说明）
npm start              # 用已构建的 out/ 启动（开发用）
```

> **候选包一律走 `npm run release:build`**（唯一目录 + 登记 + 核验）。
> `npm run dist` 只做本地开发验证，产物写入中性的 `release-dev/`，
> 不进入、也不得覆盖任何 `candidate-*` 历史证据目录（复审 G4）。

`npm run dist` 需要下载 Electron 发行包与 electron-builder 二进制，直连 GitHub 可能超时，可用镜像：

```bash
ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/ \
ELECTRON_BUILDER_BINARIES_MIRROR=https://npmmirror.com/mirrors/electron-builder-binaries/ \
npx electron-builder --win --dir
```
