## 相对 alpha.9 的变化（封面固定不透明 X3c）

本候选是**纯观感与可读性模型**回合：换肤服务的判定、事务、备份、恢复逻辑与 IPC 契约
零改动；变化收敛在注入 CSS、`surfaces`/`report` 可读性模型与模拟预览。
取证与定案文档在 `handoff/visual-fix-r2-plan-2026-09-25/X3-EVIDENCE.md`（追加取证节）。

- **封面取证更正（闭合 alpha.9 的遗留问题）**：把官方 bundle 全部 836 个渲染层 chunk
  重新扫了一遍，坐实**新布局的「新建会话页」其实是一条独立路由**（懒加载
  `new-session-*.js`，根容器 `data-component="session-new-design"`，主 bundle 出现 0 次）——
  大字 opencode 标语是 `WordmarkV2` 水印 SVG，输入框直挂封面子树，**不经过会话内的停靠容器**。
  alpha.9 记录「封面与会话内同组件、无区分属性、留待真机坐实」只对**旧布局**封面成立；
  封面限定锚点找到了，`:has()` 结构疑点就此闭合，不需要真机再定结构。
- **封面两处固定不透明（X3c，默认观感变化）**：按「透明度固定、不随设置变化、尽可能不透明」
  的口径——
  - 封面输入框底色钉为**面板色实色**（alpha 恒 1，深浅仍随主题明暗推导，边框沿用 0.9）；
  - 大字标语把官方 SVG 内部的三层 opacity（连乘约 6.7%）与下半截渐隐遮罩**钉为 1**，
    即清晰的实色大字，不再是在壁纸上发虚的水印；
  - **这两处不受「面板不透明度」滑杆影响**；会话内输入框、对话框与旧布局封面照旧随滑杆，
    用户控制权不缩水。旧布局封面的「Build anything」柔和描边（alpha.9 的 X3）保留。
- **可读性报告新增两条目（28 → 30 项）**：新增「封面输入文字」（按固定实色底计算）与
  「封面大字标语」（大字目标值），这两项的判定结果**不随面板不透明度滑杆变化**（单测钉死），
  报告口径与真机渲染一致；模拟预览补「封面示意」块，按同一固定值渲染、拖滑杆不动，与真机同构。

回归：单测/集成/e2e 在发布门禁内全绿（数字以 §1 登记块为准）；X1/X3/X3c 的**同窗口
真机应用验证尚未执行**（依赖 jc 在场的真机窗口，见已知限制）。

## 这个版本能做什么

给 OpenCode Desktop 换一张本地背景图：从图片里取色，自动推导一整套界面配色，
调好遮罩与面板透明度后写入安装。写入前自动备份，随时可以恢复。

| 项 | 范围 |
|---|---|
| 系统 | **Windows x64**（开发与测试都在此完成；**没有**在 Windows 11 上实测，不声称支持） |
| 目标（完整验证） | **OpenCode Desktop 1.18.29**，用户级安装（`%LOCALAPPDATA%\Programs\@opencode-aidesktop`） |
| 目标（结构验证通道） | 未列入白名单的版本，仅当结构验证通过并可显式确认才可应用；真机 1.18.31/1.18.32 实测结构兼容（锚点唯一、变更集合干净），但**未做完整行为验证** |
| 图片 | 静态 **PNG**、**JPEG**（`.jpg` / `.jpeg` / `.jfif` / `.jpe`）、**WebP**；≤ 20 MiB，≤ 40 MP |
| 不做 | 动图（动画 WebP / APNG）、GIF、AVIF、TIFF、BMP、HEIC、SVG |

升级 OpenCode 后定制会失效（自动更新同样会覆盖），需要重新应用；
重新应用前工具会自动重验结构，官方整体更新会走自动重新接管（alpha.5 起），
版本大改导致落点变化时会拒绝而不是写坏。

## 五步使用

1. **完全退出 OpenCode**：不是关窗口 —— 检查托盘区（时间旁边的小箭头）里有没有它的图标，
   有就右键退出。运行中工具会拒绝写入（这是保护，不是故障）。
2. **选图或拖图**：支持上面列出的格式；扩展名只用于筛选，格式按实际内容识别。
3. **调滑杆**：把「背景遮罩」和「面板不透明度」调到字看得清；不想手调就点
   「自动调整」，工具按图片亮度与细节量推一组参数并自检。面板不透明度的调法：
   调高 → 文字更清楚、背景更淡；调低 → 背景更明显、文字风险更高。
   「检查」选项卡的可读性面板默认收成一行结论条：未达标会展开并点名余量最差
   的一项，全达标则收起——点结论条可随时展开看 30 项明细。
   注意：**新建会话页的大字与输入框是固定不透明的**，不受这个滑杆影响（X3c 口径）。
4. **应用**：非白名单版本（徽章「结构验证通过」）会先弹逐项结构检查确认框；
   可读性未达标会弹显式确认框列出未达标项，核对后进入应用确认框——
   列出安装位置、版本、将要修改的条目、备份位置与所需磁盘空间
   （约「归档 ×4 + 64 MiB」）。确认后写入，写入完成会用 hash 复核。
   若目标在接管后自动更新过且满足自动重新接管条件，进度里会告知「已自动更新基线」。
5. **重新打开 OpenCode 看效果**：点状态栏最左侧的「启动 OpenCode」按钮即可——
   走的是和你双击图标同一条系统启动路径，对话照常加载；OpenCode 已在运行时
   按钮变成「打开 OpenCode」（单实例应用，只会把已有窗口带到前台）。

## 怎么恢复

右栏切到「恢复」选项卡，最多三个入口，按你机器上实际有哪些快照出现：

- **恢复上一主题** —— 回到上一次应用之前的样子，保留最近 3 份。
- **恢复到首次接管时** —— 回到本工具第一次接管该安装时的状态。
  **它不承诺是出厂界面**：接管时安装可能已被别的工具改过；目标自动更新并重新接管后，
  该快照仍是旧版本的归档，恢复到它会回到旧版本画面。
- **恢复原版** —— 只在登记过该版本出厂指纹、且备份与指纹吻合时才出现；
  **当前指纹表为空**，所以正常不会看到这个入口。

要回到真正的出厂状态，请重新安装 OpenCode。
恢复后同样**完全退出并重启**再确认。

备份默认在 `%LOCALAPPDATA%\OpenCodeThemeSwitcher\instances\<实例>\backups\`。
注意：**删掉工具目录不等于撤销主题**（归档里的定制还在），同时会失去恢复能力。

## 已知限制（如实列出）

- 未签名；没有代码签名证书。安全软件可能拦截，请记录提示内容，**不要关闭系统防护**。
- 基线门的自动重新接管是**结构级判定，非密码学校验**；不满足五条件的更新（如官方大改
  布局）仍会拒绝，需要等本工具适配后重试，不要按旧快照强行降级。
- 完整真机验证只做过一个 OpenCode 版本（1.18.29）；其余版本走结构验证通道放行，
  通过只意味着「注入机制结构适用」，不承诺界面效果逐项正常。
- 未在干净的非开发环境验证过（A6 按用户决定跳过，平台声明仅开发机 Windows x64）。
- 便携包约 133 MB（未压缩约 341 MB），因为内含 Electron 运行时。
- 背景资源在归档里固定命名为 `oc-theme-background.jpg`，非 JPEG 内容也落在这个名字下
  （按原图字节写入，未做统一转码）。
- 终端（`.xterm`）与 `--syntax-*` / `--markdown-*` 语法高亮不在覆盖范围内（有意为之）。
- 真机走查遗留一处 P3 外观缺陷：主题下顶部栏右侧色块尺寸观感不佳（不影响功能与可读性）。
- 「自动调整」的推导目标是**可读性达标**而不是「最好看」：遮罩会被自检逐步上调，
  不满意直接拖滑杆覆盖即可。
- 可读性放行**只绕对比度门**：接受的是「文字可能难读」的后果，正文对比度底线
  仍硬拦；放行不记住选择，每次应用都要重新确认。
- 「启动 OpenCode」按钮走系统启动路径，实测会话完整恢复；但「启动后直接发消息」
  的实发核验只做到输入框就绪（避免耗配额/污染会话），发送链路核验留待反馈。
- 预览与真机的观感对齐到 F4-DIFF / W5-EVIDENCE / X1 同函数口径，但**预览不等于真实窗口**：
  背景图 cover 裁切基准、文本选区交互（::selection）、缩略图分辨率等固有差异见
  相应文档「限」类；模拟预览的「封面示意」块演示固定值与滑杆脱钩，但布局形态仍从简。
- 封面固定不透明依赖官方 DOM 锚点 `session-new-design`（1.18.32 取证）；官方改版
  命中不到时这两处**退回随滑杆的半透明组**（失效方向是无害的：不会白盒、不会误伤）。
- 本候选发布时，X1/X3/X3c 的**同窗口真机应用验证未做**（菜单不透明面、封面两块清晰
  且拖面板不透明度滑杆纹丝不动、会话内输入框无回归三项，依赖 jc 在场的真机窗口）；
  X2 为本工具界面改动，已过 e2e 与截图目检，不涉真机。
- 本候选发布时，W1–W5 与 X1–X3c 后的**整体观感回执仍未做**（逐项取证已过，整体感受待反馈）。
- 本便携包未做 Electron fuse 加固（RunAsNode 等均为默认值），且未签名。

## 出问题了怎么反馈

给这几项就够（**不需要**发图片、聊天记录或完整用户目录）：

1. 工具版本（`0.1.0-alpha.10`）与候选包 SHA256（见与 zip 一同分发的 `*.zip.sha256.txt`，不在 zip 内）；
2. 报错码与状态栏那行中文提示（原文照抄）；
3. 操作时间（精确到分钟）；
4. 目标 OpenCode 版本，以及徽章是白名单绿还是「结构验证通过」蓝；
5. 若界面显示「待恢复」，把它给出的操作 ID 一并附上。

日志目录：`%LOCALAPPDATA%\OpenCodeThemeSwitcher\`，记录的是路径与哈希，
不含图片内容、也不含你与 AI 的对话。
