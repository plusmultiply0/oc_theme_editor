## 相对 alpha.6 的变化（界面修复轮 F1–F4）

本候选仍是**呈现层与交互层**修复：换肤服务的判定、事务、备份、恢复逻辑与 IPC 契约
**零改动**（F1 属删除废弃通道，见下），不改对用户安装的实际写入行为。

- **删「启动 OpenCode」按钮（F1）**：实测按钮 spawn 拉起的 OpenCode 环境不完整、
  加载不了对话，属于误导入口——整条链路（按钮、IPC 通道、主进程 launch 与对应单测）删除，
  改由用户照常双击启动 OpenCode。
- **删工具窗口默认菜单栏（F2）**：去掉 File/Edit/View/Window/Help 菜单栏，窗口更干净。
- **新增「自动调整」按钮（F3）**：选图后一键推导参数——按图片代表色亮度线性推遮罩
  （0.55–0.85）、面板恒 0.85、按缩略图边缘占比推模糊（0/4–8px）；推导后自动跑
  可读性自检，不达标逐步上调遮罩（+0.05 封顶 0.95，至多 8 次），全不过停在最优值并如实提示。
- **预览与真机观感对齐（F4）**：先做注入 CSS 与预览 mock 的逐项差异清单
  （`handoff/ui-fix-plan-2026-09-24/F4-DIFF.md`），再按清单修复九处（实底、边框口径、
  焦点环、禁用态、diff 行底、气泡边框、圆角、弹层阴影、侧栏选中示意）。四项存疑项
  经官方 CSS 取证 + 真机同图同参截图对比定案：气泡实无框、用户气泡圆角 10px、
  菜单靠「0.5px 暗环+投影」而非边框、侧栏选中为中性提亮而非主色块。
  预览的取色与透明度参数继续与写入归档**同一来源**，本轮只对齐外观表达。

回归：单测/集成/e2e 在发布门禁内全绿（数字以 §1 登记块为准）；
F4 的真机对比操作（apply → 截图 → restore previous）已于 2026-09-24 完成并恢复原状。

## 这个版本能做什么

给 OpenCode Desktop 换一张本地背景图：从图片里取色，自动推导一整套界面配色，
调好遮罩与面板透明度后写入安装。写入前自动备份，随时可以恢复。

| 项 | 范围 |
|---|---|
| 系统 | **Windows x64**（开发与测试都在此完成；**没有**在 Windows 11 上实测，不声称支持） |
| 目标（完整验证） | **OpenCode Desktop 1.18.29**，用户级安装（`%LOCALAPPDATA%\Programs\@opencode-aidesktop`） |
| 目标（结构验证通道） | 未列入白名单的版本，仅当结构验证通过并可显式确认才可应用；真机 1.18.31/1.18.32 实测结构兼容（锚点唯一、变更集合干净），但**未做完整行为验证** |
| 图片 | 静态 **PNG**、**JPEG**（`.jpg` / `.jpeg` / `.jfif` / `.jpe`）、**WebP**；≤ 20 MiB，≤ 40 MP |
| 不做 | 动图（动画 WebP / APNG）、GIF、AVIF、TIFF、BMP、HEIC、SVG |

升级 OpenCode 后定制会失效（自动更新同样会覆盖），需要重新应用；
重新应用前工具会自动重验结构，官方整体更新会走自动重新接管（alpha.5 起），
版本大改导致落点变化时会拒绝而不是写坏。

## 五步使用

1. **完全退出 OpenCode**：不是关窗口 —— 检查托盘区（时间旁边的小箭头）里有没有它的图标，
   有就右键退出。运行中工具会拒绝写入（这是保护，不是故障）。
2. **选图或拖图**：支持上面列出的格式；扩展名只用于筛选，格式按实际内容识别。
3. **调滑杆**：把「背景遮罩」和「面板不透明度」调到字看得清；不想手调就点
   「自动调整」，工具按图片亮度与细节量推一组参数并自检。面板不透明度的调法：
   调高 → 文字更清楚、背景更淡；调低 → 背景更明显、文字风险更高。
   「检查」选项卡里的可读性概要会告诉你余量最差的一项；点「明细」看每一行。
4. **应用**：非白名单版本（徽章「结构验证通过」）会先弹逐项结构检查确认框，
   核对后进入应用确认框——列出安装位置、版本、将要修改的条目、备份位置与所需磁盘空间
   （约「归档 ×4 + 64 MiB」）。确认后写入，写入完成会用 hash 复核。
   若目标在接管后自动更新过且满足自动重新接管条件，进度里会告知「已自动更新基线」。
5. **自己启动 OpenCode 再看效果**：本版本起工具内不再代启动应用（代启动的环境拉不起
   对话），直接双击桌面/开始菜单的 OpenCode 即可。

## 怎么恢复

右栏切到「恢复」选项卡，最多三个入口，按你机器上实际有哪些快照出现：

- **恢复上一主题** —— 回到上一次应用之前的样子，保留最近 3 份。
- **恢复到首次接管时** —— 回到本工具第一次接管该安装时的状态。
  **它不承诺是出厂界面**：接管时安装可能已被别的工具改过；目标自动更新并重新接管后，
  该快照仍是旧版本的归档，恢复到它会回到旧版本画面。
- **恢复原版** —— 只在登记过该版本出厂指纹、且备份与指纹吻合时才出现；
  **当前指纹表为空**，所以正常不会看到这个入口。

要回到真正的出厂状态，请重新安装 OpenCode。
恢复后同样**完全退出并重启**再确认。

备份默认在 `%LOCALAPPDATA%\OpenCodeThemeSwitcher\instances\<实例>\backups\`。
注意：**删掉工具目录不等于撤销主题**（归档里的定制还在），同时会失去恢复能力。

## 已知限制（如实列出）

- 未签名；没有代码签名证书。安全软件可能拦截，请记录提示内容，**不要关闭系统防护**。
- 基线门的自动重新接管是**结构级判定，非密码学校验**；不满足五条件的更新（如官方大改
  布局）仍会拒绝，需要等本工具适配后重试，不要按旧快照强行降级。
- 完整真机验证只做过一个 OpenCode 版本（1.18.29）；其余版本走结构验证通道放行，
  通过只意味着「注入机制结构适用」，不承诺界面效果逐项正常。
- 未在干净的非开发环境验证过（A6 按用户决定跳过，平台声明仅开发机 Windows x64）。
- 便携包约 133 MB（未压缩约 341 MB），因为内含 Electron 运行时。
- 背景资源在归档里固定命名为 `oc-theme-background.jpg`，非 JPEG 内容也落在这个名字下
  （按原图字节写入，未做统一转码）。
- 终端（`.xterm`）与 `--syntax-*` / `--markdown-*` 语法高亮不在覆盖范围内（有意为之）。
- 真机走查遗留一处 P3 外观缺陷：主题下顶部栏右侧色块尺寸观感不佳（不影响功能与可读性）。
- 「自动调整」的推导目标是**可读性达标**而不是「最好看」：遮罩会被自检逐步上调，
  图片可能被压得更暗；不满意直接拖滑杆覆盖即可。
- 预览与真机的观感对齐到 F4-DIFF 清单口径，但**预览不等于真实窗口**：
  背景图 cover 裁切基准、文本选区交互（::selection）等固有差异见该文档「限」类。
- 本便携包未做 Electron fuse 加固（RunAsNode 等均为默认值），且未签名。

## 出问题了怎么反馈

给这几项就够（**不需要**发图片、聊天记录或完整用户目录）：

1. 工具版本（`0.1.0-alpha.7`）与候选包 SHA256（见与 zip 一同分发的 `*.zip.sha256.txt`，不在 zip 内）；
2. 报错码与状态栏那行中文提示（原文照抄）；
3. 操作时间（精确到分钟）；
4. 目标 OpenCode 版本，以及徽章是白名单绿还是「结构验证通过」蓝；
5. 若界面显示「待恢复」，把它给出的操作 ID 一并附上。

日志目录：`%LOCALAPPDATA%\OpenCodeThemeSwitcher\`，记录的是路径与哈希，
不含图片内容、也不含你与 AI 的对话。
