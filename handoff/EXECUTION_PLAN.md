# OpenCode Theme Switcher：Agent 执行手册

版本：计划 v1，2026-09-10。本文是待执行任务，不表示功能已经实现。

项目目录：仓库内的 `OpenCode/_Theme/_Switcher`（相对路径）。

## 1. 交付目标与五项功能

做一个本地运行、可视化操作的 Windows OpenCode 桌面换肤助手。用户不需要修改脚本、安装 Python 或填写 API Key。合格闭环：选择图片 → 生成配色 → 调整参数 → 预览 → 确认备份后应用 → 可恢复。

| 功能 | 首版具体内容 | 完成标准 |
|---|---|---|
| F1 选图 | 本地 PNG/JPEG/WebP；文件选择和拖拽；尺寸/格式校验 | 中文、空格路径正常；非法文件有原因；原图不被修改、不上传 |
| F2 自动配色 | 确定性提取代表色，生成浅色或深色语义主题；允许修改主色 | 同图同参数结果一致；主按钮、hover、pressed、选中、边框、图标和正文配色协调 |
| F3 可读性调节 | 背景遮罩、面板不透明度、背景模糊、明暗模式、对比度提示 | 调节实时生效；正文、按钮、菜单可读；不合格组合默认阻止应用并给出修正入口 |
| F4 预览 | 对话、代码块、输入框、侧栏、菜单、按钮状态、错误和 diff 的示例预览 | 与导出的 CSS 使用同一 token 数据；明确标为模拟预览，不冒充真实 OpenCode |
| F5 应用与恢复 | 识别目标、兼容性检测、备份、应用、更新主题、恢复上一主题/原版 | 无需编辑路径；失败不遗留不可恢复半成品；升级后拒绝旧版回写 |

附属必需项：本地设置持久化、错误提示、任务进度、离线可运行、便携包、README 和演示素材。它们为上述闭环服务，不扩展成新产品。

首版不做：主题商城、用户系统、云服务、AI 生图、自然语言改主题、批量适配其他 IDE、自动后台打补丁、任意 CSS/JS 导入、终端渲染主题重写。背景图用用户本地图片；发布演示只用有权使用的素材。

## 3. 总体实现路线

默认工程建议：Electron 主进程负责本地文件和系统适配，React + TypeScript renderer 负责界面，独立 TypeScript core 负责主题算法。若用户项目已有适合的栈，P0 提出最小复用方案，避免为换栈重写。

这是计划性选型，不是对当前依赖兼容性的承诺；P1 核实维护状态、安全配置和版本后锁定依赖。优先复用成熟库，不继续用字符串替换制造新脚本。

适配路线按顺序选择：

1. 精确识别用户目标的发行渠道、版本、安装形式、运行框架及来源；不要把同名分发版与上游视为同一产品。
2. 检查该目标官方文档和固定版本源码是否有满足要求的主题/背景扩展机制。CLI/TUI 文档不能直接证明桌面支持。
3. 官方机制能覆盖五项需求时，优先使用；记录限制。
4. 没有合适接口时，仅为已验证的目标实现受限资源补丁 adapter，UI 显示「非官方本地资源定制，更新可能失效」。
5. 任何签名、完整性、安全开关阻止修改时，停止此路线；不得关闭校验、修改 EXE/fuse 或规避系统安全策略。可先交付预览/导出，但不能声称已完成 F5。

核心分层：renderer → 有类型的受限 IPC → 主进程服务 → theme core / adapter / transaction store。renderer 不获得任意文件读写、shell 命令或完整 Node 权限。

推荐新目录，根部旧原型先保留不动：

```text
handoff/                 本执行计划与状态记录
src/main/                窗口、IPC、文件选择、系统服务
src/preload/             最小允许列表桥接
src/renderer/            编辑器、参数面板、模拟预览
src/core/theme/          取色、语义 token、CSS、对比度
src/core/patch/          事务状态、备份、恢复
src/adapters/            精确版本/渠道适配
src/shared/              公共类型、schema、错误码
tests/unit/              算法/状态机测试
tests/integration/       合成安装与故障注入
tests/e2e/               应用界面自动化
tests/fixtures/          合成资源、合法测试图片
docs/                    兼容矩阵、安全模型、验收、操作指南
```

运行数据用系统用户数据目录，不能放进源码、安装包或 OpenCode 用户配置目录。备份按「安装实例 ID / 操作 ID」隔离；图片、备份、manifest 不提交 git。

## 5. P1：工程骨架、公共契约与测试入口

负责人：集成 agent。依赖：G0。产物：工程配置、锁文件、`src/shared/*`、mock adapter、基础测试。

- T10：创建最小可启动工程，配置 lint、typecheck、unit、integration、E2E 和 Windows 打包命令；确定环境版本并写入 README。
- T11：窗口启用隔离、关闭 renderer Node 集成，采用适用的 sandbox/CSP 设置；不加载远程页面，不用 eval。
- T12：冻结以下数据结构，运行时也做 schema 校验，不能仅有 TypeScript 类型。

| 对象 | 必须表达的字段与语义 |
|---|---|
| ThemeSpec | schemaVersion、imageId、mode、palette、overlayOpacity、panelOpacity、blurPx、backgroundPosition |
| ThemeTokens | background/panel/text/muted/primary/onPrimary/hover/pressed/border/focus/selection；语义状态色分开 |
| TargetInfo | targetId、真实绝对路径、渠道、版本、adapterId、指纹、支持状态和拒绝原因 |
| ContrastReport | 元素/状态、前景背景、比值、目标值、通过/失败、验证范围与采样方法 |
| OperationManifest | schema、operationId、targetId、版本、adapterId、before/after/backup hashes、主题摘要、状态、时间、前序操作 |
| Result | success/data 或 error/code/message/recoveryHint；不得把异常吞成成功 |

- T13：约定桥接方法 `pickImage/importImage`、`generateTheme`、`analyzeContrast`、`discoverTargets`、`inspectTarget`、`stageTheme`、`applyTheme`、`listBackups`、`restoreTheme`、`getOperation`。
- T14：图片/目标/操作使用主进程登记的 ID。renderer 不得任意传入路径要求写文件；所有 token、枚举、数值范围在主进程复验。
- T15：操作事件带 operationId、phase、message；只有可计量时给百分比。提交阶段不可取消，准备阶段可安全取消。

验收门 G1：空工程能运行，CI/本地验证命令存在，mock 可贯通五项界面行为，公共接口有示例和测试。此后再启动并行任务。

## 6. P2：图片、配色与可读性引擎

负责人：主题 agent；负责 `src/core/theme/` 和对应 unit fixtures。依赖：G1；与 P3/P4 并行。

- T20：验证图片 magic bytes 与实际解码，不只检查扩展名；首版建议限制文件 20 MiB、解码后 40 MP，配置可调整并测试边界。支持 EXIF 方向，明确透明图片合成底色，拒绝 SVG/动画/无法解码图片。
- T21：原图只读；导入后保存工具自己的副本并计算 hash。预览缩略图和分析用缩小副本，绝不覆盖原文件。异步处理，防止大图冻结 UI。
- T22：确定性量化/聚类提取代表色，输出浅/深色语义 token；同一版本算法、同输入同参数必须一致。纯色、灰度和低饱和图片有 fallback。
- T23：以 token 模板生成 CSS，不从旧 CSS 大量 replace；样式限定到 adapter 支持的 UI token/选择器。只引用工具本地图片，不接受远程 URL、@import 或用户执行代码。
- T24：首版参数：背景遮罩 0–1、面板不透明度 0–1、背景模糊 0–20 px、自动/浅/深模式、主色。模糊只作用背景层，不模糊正文；默认保护性面板保持可读。
- T25：正文及正文大小按钮标签的对比度目标 4.5:1；重要非文本控件/焦点目标 3:1，作为工程验收目标，不把局部测量宣称为完整无障碍合规。禁用态单独列出，不混算。
- T26：透明背景要按图像、遮罩和面板合成后的颜色计算，不只比较两枚 token；自动修正只改文字/遮罩/面板参数，不改用户原图。采样只能称估计；申请「安全通过」须有保守界限或对实际最终显示区域充分验证，否则提示未验证并使用实底保护层。
- T27：终端维持原渲染方案；代码语法、错误/警告/成功、增删 diff 保留可区分语义。不用全局 `* { color: ... !important }`。

验收：至少覆盖纯黑/白、灰度、透明、高频棋盘、明暗混合、中文路径、损坏图、超限图；CSS 稳定、图片 hash 不变、参数可重放、对比度失败可重现且修正后通过。

## 7. P3：兼容 adapter、事务应用与恢复

负责人：系统 agent；负责 `src/adapters/`、`src/core/patch/` 和 integration tests。依赖：G1；第一版风险最高。

### 7.1 识别与拒绝条件

- T30：安装发现只扫明确候选位置/登记信息；手动选路径后验证真实目标，不全盘搜索。路径 canonicalize 并处理大小写、junction/symlink；拒绝越界和伪造 manifest 路径。
- T31：adapter 明确声明版本、渠道、资源布局和允许修改集合。不能因文件叫 app.asar 就推断兼容；如果实际框架不是 Electron，不能套用 ASAR 方案。
- T32：操作前检查进程与写权限；无法确认目标已退出则拒绝。提示用户保存任务并退出，不强制 kill，不自动提权。只对已选目标判定，不能误伤其他同名安装。
- T33：资源签名/完整性检查应遵从目标保护机制；不修改可执行文件或安全开关。预检磁盘空间必须覆盖备份、staged 文件和事务临时文件。

### 7.2 事务与异常恢复

正常状态：`inspected → staged → backed_up → committing → applied`；失败：提交前 `failed`，提交后根据可证明的磁盘状态 `rolled_back` 或 `needs_recovery`。恢复是新操作，不改写历史操作事实。

- T34：为每安装实例获取独占锁；界面按钮禁用只是辅助，不能替代后端并发保护。
- T35：在准备区生成候选资源并验证：仅允许集合内的 HTML/CSS/图片变化，其他归档条目、unpacked 标记、链接及必要元数据完整保留。检查非法路径/归档炸弹。辅助库须纳入项目并核实许可，不依赖作者个人 `.codex` 路径。
- T36：先备份当前真实资源并验证 hash，保留首次已知原版与上一主题两种语义。工具首次接管已被其他工具修改的安装时，不能把它标为原版；无法识别则拒绝或经专门迁移方案处理。
- T37：提交前再次核对版本、目标 hash 和进程状态，检测准备期间升级/其他进程改动。短窗口竞态仍需通过锁、文件占用和提交后验证应对，不能宣称进程检查消除了竞态。
- T38：采用经 Windows fixture 验证的同卷替换机制，不把 `copyFile` 覆写大文件称作原子操作。事务日志必须先于关键写入持久化；多文件目标不能假装整体原子，须有明确提交顺序和补偿步骤。
- T39：成功后复核目标 hash 和资源可读性再标 applied。日志写入失败不能仅因 UI 报错就盲目回滚；根据 before/after hash 和事务状态判定。
- T40：启动时扫描未完成事务，只检查本工具记录的目标。状态不明/目标已外部变化时停在 needs_recovery；不得自动旧版覆盖。提供状态说明及受保护恢复入口。
- T41：提供 `恢复上一主题` 和 `恢复原版` 两个清晰入口；原版未知时禁用后者并说明。备份损坏、目标升级、hash 不符、路径异常时拒绝恢复。还原前也备份当前状态。
- T42：重复应用相同主题应 no-op 或明确提示已应用；换图/换配色更新不重复插入样式。日志默认脱敏路径，不采集对话、token、账号信息。

### 7.3 必须完成的故障测试

逐个在合成 fixture 注入：stage 失败、磁盘不足、备份失败、备份 hash 错、权限不足、文件占用、版本变化、提交前 hash 变化、提交中断、提交后日志失败、损坏 manifest、同时两次 apply、apply 与 restore 并发、启动遇到未完成事务。

对每项断言：安装资源最终是已验证旧版/新版或明确禁止继续的待恢复状态；可用备份不丢失；未出现静默成功。正常 apply→换主题→恢复上一个→恢复原版必须逐步核对 hash。

验收门 G3：全部 fixture 场景通过；unknown target 不可写；无需修改安全开关。未通过不得做真人安装测试。

## 8. P4：桌面界面与联调

- T56：支持键盘操作、可见焦点、125%/150% 缩放；减少透明度时降级纯色面板。外链仅允许明确安全协议并经受控系统打开。

## 10. P6：作品与交付材料

负责人：集成 agent，QA 复核。

- T70：README 写清定位、支持渠道/版本、下载安装、五步使用、恢复语义、非官方修改风险、常见报错、已知限制、开发命令。
- T71：交付 `docs/acceptance.md`、`docs/security.md`、`docs/compatibility.md`、CHANGELOG、依赖/素材许可说明。
- T72：制作 60–90 秒演示：原界面→选图→取色/调节→模拟预览→真实应用→恢复；无真实验收时不得剪出暗示已成功的演示。
- T73：准备掘金文章提纲：痛点、功能 GIF、AI 协作过程、技术难点、备份/恢复安全设计、效果和限制、仓库链接。活动规则、日期在实际发布前重新核实。
- T74：输出便携包、SHA256、测试报告及待办项；公开仓库/发文/上传安装包须另获用户授权，不由 agent 自行发布。

最终 DoD：F1–F5 每项标记 PASS/FAIL/BLOCKED 并有证据路径；没有未解决的数据破坏风险；用户从安装到恢复无需编辑源码；所有未验证环境和功能明确列出。

## 11. Agent 分工、依赖与防冲突

| Agent | 任务 | 文件所有权 | 依赖 |
|---|---|---|---|
| 集成 | P0/P1/P6、合入、打包 | shared、main/preload、工程配置、锁文件、文档 | 最先启动 |
| 主题 | P2 | core/theme、对应 unit tests | G1 |
| 系统 | P3 | adapters、core/patch、integration tests | G1 |
| 界面 | P4 | renderer、界面 E2E | G1，先 mock |
| QA | P5 独立检查 | 验收报告、故障用例，修复交回模块 owner | 可从 G1 设计用例，整体验收在集成后 |

依赖：P0 → P1 →（P2 / P3 / P4 并行）→ P5 → P6。P3 没通过不应以界面完成率宣称接近可发布。

- 单 agent 可照同一顺序执行，不需要为了计划自动创建多个任务。
- 多 agent 不同时修改 shared、锁文件和入口桥接；变更契约先提交给集成 agent 决定，再更新消费者。
- 有 git 可用独立 worktree/分支；若采用默认前缀使用 `codex/`。无 git 时按目录所有权协作，不同时写同一文件。
- 每个任务交接：任务 ID、变更文件、测试命令及退出码、证据位置、阻塞、下一步。未执行写「未执行」，禁止编造通过。
- 新增依赖统一由集成 agent 更新和安装。不要提交构建缓存、用户图片、备份、大型 app.asar。

## 12. 工作量与裁剪顺序

以下仅为排期估计，不是完成时间承诺：P0 0.5–1 天，P1 0.5 天，P2 1–1.5 天，P3 2–3 天，P4 1–2 天，P5 1–2 天，P6 0.5 天。总体约 6.5–10.5 人日；适配新框架/官方接口不足时重新估算。

时间紧时依次裁掉：额外主题预设、多种背景定位、额外动画、次要窗口尺寸美化、第二个适配版本。不得裁掉备份校验、未知版本拒绝、故障恢复、主流程对比度和真实验收。官方接口适配成本大幅变化时先调整路线，不硬做 ASAR。

## 13. 可直接发给执行 agent 的提示词

### 集成/单 agent 开工

> 在项目仓库根目录工作。先完整读取 handoff 目录下的 EXECUTION_PLAN.md、task_plan.md、findings.md、progress.md，再检查项目规则、现有文件和 git 状态。执行 P0，产出 discovery、compatibility、architecture；然后按依赖推进已获授权的开发。保留旧原型与用户改动，禁止直接运行旧换肤脚本，禁止修改 OpenCode 安装/强制关应用/降低安全检查；真实应用测试先请求明确授权。优先官方接口；仅对核实的渠道和版本实现 adapter。每阶段记录文件、测试与证据，不把 fixture 通过当成真实视觉通过。若 P0 无安全应用路线，停止 F5 开发并向用户报告可选范围。

### 主题 agent

> 阅读 handoff 四份文档和已冻结 shared 契约，仅负责 P2 与其 unit tests。实现本地图片导入校验的核心部分、确定性取色、语义 token、CSS 和合成背景对比度分析。与主进程 owner 对接文件入口，不扩张 IPC 权限；不修改 adapters、工程锁文件或用户安装。提交 T20–T27 逐项证据和边界测试。

### 系统 agent

> 阅读 handoff 文档、P0 的兼容证据和 shared 契约，负责 P3 与 integration tests。只在合成 fixture/获准的资源副本中开发，落实目标识别、白名单、备份、事务日志、恢复和故障注入。未知目标/签名保护/进程状态不明时拒绝写。区分上一主题和原版，验证 Windows 替换语义；不把简单复制称为原子提交。不得实际修改用户安装。

### 界面 agent

> 阅读 handoff 文档和 shared 契约，负责 P4。优先使用 mock 完成五项闭环和九类状态，随后对接真实 API。预览与主题 core 共用 token，并明确是模拟预览；应用前展示目标、备份与风险。保证键盘、缩放、错误和长内容场景。禁止 renderer 直接获得文件写入或 shell 权限，不改 shared/锁文件；接口问题交集成 owner。

### QA agent

> 根据 handoff 第 7、9、10 节独立审查和执行获准测试，建立 F1–F5 验收矩阵和故障报告。重点找旧版误恢复、并发写入、崩溃事务、路径逃逸、预览/真实效果不一致、原机器依赖。记录实际命令/退出码与截图证据，不编造运行结果。未经用户授权不触碰真实安装、不发文、不发布包；将缺陷交相应模块 owner 修复后复验。
