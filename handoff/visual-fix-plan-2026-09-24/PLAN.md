## W1：输入框白条修复（一提交）

**现象**（图 1）：聊天输入区外层容器有一条横贯的白底带，输入框本体窄于它，两侧露出白条。

**步骤**：
1. 取证（只读）：真机 OpenCode 里用开发者工具或注入探针确认输入区 DOM 层级与计算样式，定位「白底带」来自哪个元素（外层容器背景 / padding 区透出面板底色）；对照 `css.ts` 现有输入区选择器，确认是选择器漂移还是覆盖不全；
2. 修复：调整 `css.ts` 输入区规则——目标效果二选一（取证后定）：(a) 输入条全宽化消除侧带；(b) 外层容器背景改透明/同源面板色，让白条消失；
3. mock 预览同步：`.input` 区域按同一结论改，保持「预览=注入」同构；
4. 验收：typecheck/lint/unit 全绿；真机应用后截图确认白条消失；预览截图同图对比。

**边界**：只动输入区规则；token 与 alpha 仍同源；不借机改其它区域。

## W2：配色与遮罩推导调优（一提交）

**现象**（图 2）：整体观感「洗白」——Shell 卡片白得发闷、文字区对比弱、壁纸存在感过低，和「蓝白克制」的目标观感有距离。

**步骤**：
1. 定方向（先出小样再改码）：用现有自动调整的推导路径，对图 2 同款浅色系壁纸试 2–3 组参数（遮罩 ↓、面板不透明度 ↓、面板底色由纯白改带主色倾向的浅中性色），截图给 jc 定方向，**不替他拍板观感**；
2. 实现：把选定方向落到推导逻辑（`generate.ts` 遮罩曲线 / `surfaces.ts` 面板底色映射 / 默认值），保证深浅两类壁纸都不回退到「白糊」；
3. 自检：推导后跑 `analyzeContrast`，仍必须过既有可读性标准（本项不降低标准，W3 才负责放行）；
4. 验收：单测覆盖新推导区间（深图/浅图各断言参数范围）；真机截图前后对比。

**边界**：只调推导与默认值，不动对比度阈值；历史报告口径（report.ts 条目模型）不变。

## W3：可读性门软化——显式确认后允许应用（一提交）

**现状**：`operation-service.ts:150-160` 在 `report.passed === false` 时直接 `CONTRAST_BELOW_TARGET` 拒绝；renderer 只能提示用户回去调参。

**设计**（默认仍拦截，放行必须显式）：
1. IPC 契约：`StageThemeInput` 增加可选 `allowContrastOverride?: boolean`（schema 校验，默认缺省=false）；
2. 主服务：报告未过且未带 override → 照旧拒（错误体附未达标项明细，供 UI 展示）；带 override → 放行，并在结果与事务日志里**如实记录** `contrastOverride: true` + 未达标项清单（归档证据可查）；
3. UI：应用被 `CONTRAST_BELOW_TARGET` 拦下时，弹出确认区——列出未达标项 + 一句后果说明（「文字可能难以辨认」）+ 「仍要应用」确认钮；点了才带 override 重提。确认区不得默认勾选、不得记住选择；
4. 验收：单测——无 override 仍拒、有 override 放行且结果带记录、schema 拒绝非布尔值；typecheck/lint 全绿。

**边界**：override 只绕过对比度门，其余门（结构验证、基线、进程锁）一律不绕；恢复链路不受影响。

## W4：启动按钮复活（先验证，后实现；验证一提交，实现一提交）

**背景**：F1（alpha.7 已含）删按钮的原因：`spawn` 直拉起的 OpenCode 会话加载不了（子进程环境残缺）。jc 本轮给出复活条件：**模拟用户双击启动且会话正常加载**。

**W4a 可行性验证（一提交，纯探测）**：
1. 写一次性探测脚本（`tools/` 下，不入产品链路）：用 ShellExecute 等价路径拉起 OpenCode——候选方式按优先级：`cmd /c start "" "<exe>"`、`explorer.exe "<exe>"`、PowerShell `Start-Process`；三者均 detached、不持句柄；
2. 真机验证（jc 参与）：每种方式启动后开一个会话，确认会话内容正常加载、可发消息；
3. 结论入档：哪种方式达标（或全不达标）写进本目录证据文件。
**gate**：只有一种方式实测达标才进 W4b；全不达标 → 把「不可行及原因」写进兼容性文档定论，按钮不做，本项关闭。

**W4b 实现（一提交，仅当 W4a 达标）**：
1. 新 launch 链路按 F1 反向重建，但启动方式换成 W4a 验证达标的 ShellExecute 路径；安全边界不变：renderer 只传 `targetId`，exe 路径由主进程按 adapter 声明解析；
2. 按钮位置沿用上轮状态栏左侧；running 时文案「打开 OpenCode」；
3. 验收：单测（路径解析、exe 缺失干净报错、spawn 参数正确）+ 真机一次启动+会话加载确认。

**边界**：绝不恢复旧 `spawn` 直拉方式；未过 W4a 不动产品代码。

## W5：模拟预览背景图保真（一提交）

**现象**：F4 已对齐结构，但背景图呈现（壁纸层的观感）仍与真机有差距。

**步骤**：
1. 诊断（先行小提交或并入实现提交的证据部分）：逐项 diff 注入 CSS 背景层与 mock 预览——cover/position 方式、模糊 inset、遮罩叠加层序、缩放系数（预览是缩比渲染，模糊半径需按比例折算，这是常见差距源）；
2. 对齐：按清单修 mock 样式；若发现注入层本身有问题（而非预览错），单独评估，不借 preview 修注入层；
3. 验收：同一张壁纸真机截图 vs 预览截图并排目检；单测不回退。

**边界**：mock 只改呈现，token 同源红线不动；差距若来自「缩比渲染的物理极限」（如模糊观感），如实写进预览注释，不硬凑。
