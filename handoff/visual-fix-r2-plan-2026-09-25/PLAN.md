## X1：下拉菜单做深不透明（一提交）

**步骤**：
1. 把菜单/弹层选择器（`menu-v2-*`、`dropdown-menu-*`、`context-menu-*`、`session-tab-popover`；tooltip 一并评估）从 `css.ts:170-186` 共享组拆出，单列一组规则；
2. 菜单面改用**不透明深色面**：alpha=1（或 ≥0.97 的近实色），底色取 panel 色或按 mode 再加深/提亮一档（`generate.ts` 已有 lighten/darken 工具）；border 保持 0.9；
3. 对比度自证：菜单文字（`tokens.text`）对新底色的对比度纳入 `report.ts` 条目模型或至少单测断言 ≥4.5——不能只改不测；
4. mock 预览如有菜单示意则同步（无则在预览注释里说明菜单不在预览覆盖范围）；
5. 验收：单测断言菜单规则输出实色（rgba alpha=1）且对比达标；typecheck/lint/unit 全绿；真机打开 Build/模型选择器、会话标签弹层截图确认文字清晰。

## X2：可读性检查面板折叠收纳（一提交）

**方案（默认采 A，B 备选）**：
- **A. 面板级折叠（默认）**：面板默认收成一行结论条——「✓ 全部条目达标（估算）· 最差 错误提示 4.66/4.5」或「✗ N 项未达标」；点结论条展开整卡（代表性底色、最差项、28 项明细的现有结构原样保留在内）。未达标时**默认展开**（需要用户看到问题），全达标时默认收起。
- B. 子选项卡：「检查」内再分「概要/明细」——多一次点击，信息 scent 差，不采，除非 jc 点名要。

**步骤**：

2. e2e 选择器核对：`.entries li` 等断言在深层 details 内，面板级折叠后需同步打开或调整（逐个 grep 确认，能不改不改）；
3. 验收：typecheck/lint/unit/e2e 相关用例全绿；截图确认默认态一行、点击展开完整。

**边界**：只动呈现，报告数据与判定逻辑一行不动。

## X3：封面标语与输入框降透明（一提交）

**需求精确化（jc 2026-09-25 13:30 补充，覆盖原 X3 表述）**：新建会话页的大字 opencode 标语与输入框，透明度**固定、不随设置（面板不透明度滑杆）变化，尽可能不透明**。即这两处脱离 spec 参数，用写死的近实色/实色。

**步骤**：
1. **取证（先行，只读）**：真机 1.18.32 新建会话页取 DOM 证据——
   - 大字标语容器的组件标识，及其文字透明的来源（opacity / 半透明 color / 无底色直接叠壁纸）；
   - 封面输入框的组件标识与上下文选择器（判断是否与会话内 `dock-prompt`/`prompt-input` 同组件；同组件则必须拿到封面限定的上下文选择器，不能全局改）；
   - 证据按 W1 先例写 `handoff` 证据文件；
2. 修复（两处都写成**固定值**，不接 `panelAlpha(spec)`）：
   - 封面输入框：固定 alpha=1（实色）；底色仍按 mode 取 panel 色（深色模式深底/浅色模式浅底），**只是 alpha 不再读设置**；
   - 大字标语：固定 opacity=1 的实色文字；因壁纸任意，纯文字色无法对所有壁纸保证对比——默认加同源实色衬底或文字阴影（取证后按官方结构二选一，优先改动最小的），保证「尽可能看得清」；
3. 可读性模型同步：`report.ts`/`surfaces.ts` 里这两处按**固定 alpha** 参与对比度计算（不再随 panelOpacity 变），保证报告口径与真实渲染一致；滑杆调参时这两项的判定结果不应再变化——加单测固定这个行为；
4. mock 预览同步：预览新建会话页示意按同一固定值渲染，且预览里调滑杆时这两处不变（与真实同构）；
5. 验收：单测——输出 CSS 中封面组规则为固定实色、不引用 spec 面板 alpha；滑杆变化不影响这两项报告条目；typecheck/lint/unit 全绿；真机新建会话页截图确认大字与输入框清晰，且拖面板不透明度滑杆这两处纹丝不动。

**边界**：选择器必须来自取证证据，不猜；固定只限封面这两处，会话内输入框与其余面板仍随设置（用户控制权不缩水）；「固定」指 alpha 固定，底色仍随明暗模式，避免深色模式出现白盒。
